# Historical calendar import

7 November 2026. Source, hosted SQL, native SDK, browser and Production evidence are tracked separately below. Founder acceptance remains open in the [shareable checklist](../../public/qa/historical-calendar-checklist.md).

## Behavior and security boundary

Settings adds a CSV importer for actual same-school Admin/Principal identities. A current native Auth session with verified TOTP/AAL2 is required for preview and commit; metadata roles, Teacher/family roles, foreign-school IDs and logged-out sessions do not confer access. AAL1 Office context is read-only. Existing school-detail permissions stay unchanged.

CSV uses exactly `date,status,label`, at most 366 records and 64 KB, with real civil dates, working/holiday statuses and required 1–120 character labels. The selected supported finite academic year bounds every date; each date is strictly before server Today in Asia/Kolkata. Calendar facts are schoolwide, including attendance from other overlapping years. No weekdays or missing dates are inferred. Any existing configured day, including the same requested decision, blocks the all-or-none import.

Server preview binds the actor, school, year and bounds, normalized rows, revision and all displayed attendance counts in a SHA-256 token. Commit serializes school-calendar writes, locks matching retained marks, recomputes the snapshot and rejects stale impacts. A 5–300 character reason and explicit acknowledgement are required. Receipts are actor/request-bound; an exact retry returns the existing response after current permission/MFA checks, while changed-payload replay is rejected. Future legitimate attendance corrections can change later reports independently.

One private RLS-protected table retains immutable historical day facts, linked to the existing receipt. There are no grants on that table to public/anonymous/authenticated/service clients. Public RPCs are INVOKER wrappers over private checked routines with empty search paths. Imported facts resolve only where no effective weekday policy exists; existing rules win. Import provenance carries its own revision and no Teacher correction-window policy. The current policy active today continues to govern new Teacher requests.

Attendance rows are never inserted, updated or deleted by import. Preview shows six status counts and distinct pupils **with saved marks**, not an invented total of all pupils affected by reporting. Marked holidays are allowed only with an explicit reporting warning and acknowledgement: retained marks remain visible, while school closed days are excluded from the official rate. A working date with legacy pupil Holiday can still produce an unresolved/null rate. The existing approved daily-v1 formula and fail-closed enrollment/mark checks are unchanged. Fee, child-link and notification/read state are not mutated, and no historical alerts are generated.

## Missing-mark correction concurrency fence

Forward migration `20261107124633_serialize_attendance_corrections_with_calendar_imports.sql` adds the school-calendar shared advisory lock to correction review before correction/attendance row locks, then rechecks native actor and Office role after waiting. Import holds the matching exclusive lock. Review-first changes the fresh preview; import-first makes review wait until the import completes. Later legitimate corrections remain allowed.
