# Office gate operations

7 November 2026. [Founder checklist](../../public/qa/gate-operations-checklist.md) · [Stable Production](https://sms-web-shoaibhasann.vercel.app/login).

## Product boundary

Attendance adds a separate Gate operations workspace for actual same-school School Admin/Principal identities with native authenticator verification. It reuses the governed device create/revoke, pupil mapping/revocation and immutable event receipt capabilities. School selection and workspace switching are frozen during pending writes. Existing daily register, submission monitor, official reports and reviewed corrections keep their own flows.

One school has one active gateway. Setup captures an IST late cutoff and explicit fallback weekdays; configured school calendar decisions take precedence. Configuration is immutable: revoke and replace instead of silently changing historical device rules. Random 32-byte credentials stay in client memory and are revealed only after a confirmed active creation; neither raw credentials nor hashes appear in setup/event lists. Closing, account/scope changes or refocusing clear credential panels. An unconfirmed save retains its original request/credential for an exact retry while the workspace remains active. A revoked retry is shown as retired, never reactivated. Losing a credential requires revocation/replacement; there is no recovery/download service for old credentials.

The bounded pupil picker searches active same-school pupils by literal name/admission substring and requires explicit selection. Mapping preserves the canonical pupil identity; a retired device subject cannot be reassigned. New mapping does not replay old held events. Current enrollment, calendar and conflict eligibility remain checked by ingestion, rather than being inferred from successful mapping.

Event pages retain device/receipt timestamps, IN/OUT, ingestion status and reason. Optional verified pupil/device labels do not expose foreign records. Receipt attendance status is an immutable ingestion snapshot, not the current canonical mark. Held events remain read-only; this workspace does not invent an approval, replay or historical conversion policy. Existing reviewed attendance workflows remain separate. OUT retains daily presence, missing scans stay Unmarked and no provider send is activated.
