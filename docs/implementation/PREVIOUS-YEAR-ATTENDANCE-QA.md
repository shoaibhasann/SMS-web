# Previous academic-year official attendance reports

7 November 2026. [Founder checklist](../../public/qa/previous-year-attendance-checklist.md) · [Stable Production login](https://sms-web-shoaibhasann.vercel.app/login).

## Product boundary

The shared web Official attendance component adds year/month controls to Student and Parent dashboards and the Attendance page. Current session stays the initial default. Explicitly selected years survive hard refresh through a session-only preference scoped to the verified account, role, school and pupil; no report data is cached there. The raw history stays a separately labelled all-years register, with old rows retained.

The year list contains only the authorized pupil's enrolled completed years and a sole valid nonfuture current year. Archived years must end strictly before server Today in Asia/Kolkata and have a finite 1–366 day range. Unenrolled, future/staged and foreign-school historical years cannot be selected through direct RPC calls. Missing/ambiguous/unsupported current setup remains explicit while valid archives remain available; no automatic archived fallback is used. Current-session metadata retains its legacy semantics, including a valid future current session's not-started state.

Both APIs use one daily-v1 calculator: Present/Late 1, Half Day 0.5, Leave/Absent 0, excluding enrolled school closed days. Selected-year admission/promotion/move/withdrawal evidence bounds the register. Enrollment ingestion time never substitutes for a real admission date. A historical active enrollment for a pupil now withdrawn needs coherent later native withdrawal evidence; uncertain placement or incomplete/calendar/conflicting records withhold the rate. Completed-year cutoff is its year end, not today's current class or calendar period. Reports reflect current verified source records and can change after legitimate corrections.

The existing public three-argument current summary RPC and DTO remain compatible, with its private wrapper delegating to the shared calculator. New public report/context RPCs are INVOKER wrappers over private checked routines with empty search paths. Only authenticated users can execute the protected entry points; the raw calculation/auth helpers are denied to API roles. Native session, actual family role, active school/profile and current own/linked-child access are checked again after lock waits. Year/report identity and month/date/count contracts are verified in the client; account/child/year changes abort obsolete requests and remove old rates. Any access failure clears the year catalog even if another parallel response succeeded first.
