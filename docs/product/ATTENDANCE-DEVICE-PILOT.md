## Proposed software boundary

1. A dedicated school/device connector receives supported vendor events. Device credentials are separate, scoped and revocable; the hardware never receives a Supabase service role or a staff login.
2. Preserve the original event, receipt time, device time/offset and vendor identifier in a bounded private event/audit path. Normalize only documented fields. Reject unauthenticated sources and flag unknown pupils, ambiguous mappings or unreasonable clocks for review.
3. Deduplicate using the documented immutable device event/sequence contract, including offline/restart behavior. Replays, out-of-order arrival and temporary outages must not duplicate an official mark or alert. A fallback key requires a proved collision/restart policy.
4. Preserve each accepted gate observation as evidence. A valid mapped IN automatically creates/updates the existing daily class register to Present/Late using validated event time, the event-date enrollment and approved school-day/cutoff rules. Repeated IN cannot create another daily mark or duplicate alert. No punch stays Unmarked until the approved cutoff/outage policy determines otherwise. OUT records departure; it does not erase the day's presence or automatically imply Half Day. Never infer IN/OUT by alternating scans; repeated directions, missing OUT, conflicts and unreasonable clocks remain reviewable. A gate scan does not establish period-by-period classroom presence or conclusively prove who used an identifier.
5. Apply automatic marks through a narrow governed attendance capability and the existing canonical register/history, retaining the device source and event reference. Existing reviewed/locked marks, approved leave, holidays and conflicting manual marks use the defined precedence/review path rather than blind overwrite. Require the established review/reason path when a historical correction is needed. Do not create a competing attendance ledger or a general-purpose Admin API on the device.
6. Publish arrival/exit and resulting attendance notifications only from committed eligible outcomes. Reuse the existing native push queue; recheck current child links, roles, device generation, source status and recipient preferences before dispatch. Reconcile an unsent absence job if an accepted late IN changes its authoritative outcome; an already sent alert remains in history and any correction follows approved school policy. Define an approved freshness rule: offline/backlogged punches must be labelled with their actual event time and delayed status, or suppressed, never presented as "just arrived/left." Gate notification recipients, thresholds and trigger settings remain school decisions.

The proposal describes the broader physical pilot, not a claim that all of it is implemented. The ingress accepts only bounded current-day events: older offline dates are held; existing manual/leave/review conflicts are preserved; an earlier IN can improve only an unchanged device-owned mark. [The subsequent Office workspace](../implementation/GATE-OPERATIONS-QA.md) adds device management, pupil mapping and immutable held-receipt readback. It does not resolve/replay held receipts or add a vendor adapter. Optional Guardian arrival/exit inbox events and settings are implemented in the separate follow-up. The new daily-calendar foundation is Production Ready at runtime `7883753` with hosted/local and Production Admin/Teacher proof, with final post-Production preservation verified; school acceptance, official rate/overnight/period policies, real provider delivery, vendor adapters and historical conversion remain separate.
